# Governance

Fieldwork is maintained by Tedy Fazrin (@tedy69). Contributors can propose changes, review work, improve documentation, and lead an area as the project grows.

Small fixes can go directly to a pull request. Significant changes to scope, storage, synchronization, security, or public contracts start with an issue describing the problem, proposed behavior, migration impact, and alternatives. Keep decisions and their reasoning in that discussion.

The maintainer currently makes release and merge decisions. Reviewers are expected to explain requested changes. There is no promise of a review deadline. If a decision is disputed, describe a concrete alternative and its tradeoffs in the same public discussion.

New maintainers are added through a public proposal after sustained work and review participation. Permissions should match the area being maintained. Security disclosures and conduct reports are handled privately where needed.

Releases use semantic versioning. Before 1.0, minor releases may change contracts; record migration steps in the changelog. Git tags and release notes should state what was checked, including any remaining device or deployment gates.
